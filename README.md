# Office Noun

A one-page, CC0 daybook for [officenoun.xyz](https://officenoun.xyz). Plain HTML, CSS and a little JavaScript, generated from dated Markdown files.

## Add a readout

1. Add `readouts/YYYY-MM-DD.md`.
2. Write normal Markdown. The filename becomes the date heading.
3. Commit and push. GitHub Pages rebuilds the site automatically.

Files are sorted newest-first. Each entry is headed "Day N · date" and can be linked as `#d-YYYY-MM-DD`; filmstrip cards for days with an entry link there. Each source line in a paragraph ends with a line break. A leading `# YYYY-MM-DD` heading is dropped.

## The Nouns

Every office day has its own Noun. Days 1–10 are canon: the hand-made SVGs in `public/nouns/`. From Day 11 on, the head follows the same ten-day roster, and body, accessory and glasses are picked from the day number with a seeded PRNG, so a given day looks the same forever. `public/office-noun.js` does the picking and drawing in both the browser and the build. Never reorder the pools or the PRNG, or old days change.

The pools and their labels live in `scripts/vendor-traits.mjs`. To change them, regenerate `public/office-traits.js` from the official trait data (a dev-only step; the build needs no install):

```sh
npm i --no-save @nouns/assets
node scripts/vendor-traits.mjs node_modules/@nouns/assets/dist/image-data.json
```

Change the first office day in `site.config.json`; that date displays as Day 1.

## Today and org chart

Two more pages are generated by the build, so they roll over each day with the scheduled workflow.

- `/org/` is the org chart: one card per office day, 1 through today, in ten departments headed by the ten canon Nouns. Each card shows the day's Noun, title and who it reports to. Generated Nouns are written once to `public/nouns/day/NNN.svg` (git-ignored) and linked lazily.
- `/today/` is the day page: today's Noun, the date, today's desk, the lots from `site.config.json`, and the gifts note. Its small inline script only marks planned posts as done or next.

Planned posts live in `data/posts-plan.json`, an array of `{ "time": "HH:MM", "text": "...", "kind": "..." }`. Time is 24-hour in the `timeZone` from `site.config.json`. If the file is missing or empty the desk says "nothing planned."; bad entries are skipped with a warning.

## Tezos desk kit

`public/kit/` holds a small, dependency-free widget that shows a Tezos wallet: balance, pieces published, pieces held, transactions, and a grid of the latest mints, each linked to its objkt page. The site's "the wallet." section uses it for the wallet in `site.config.json`, and `/kit/` is its own page with a live demo.

Use it on any site:

```html
<link rel="stylesheet" href="https://officenoun.xyz/kit/tezos-desk.css">
<script src="https://officenoun.xyz/kit/tezos-desk.js"></script>
<div data-tezos-desk data-wallet="tz1UWibBbQXvuSkThsLUGAaL4R5j7X3PSCKj"></div>
```

Attributes: `data-wallet` (required), `data-title` (default "the wallet"), `data-limit` (default 12, 1 to 48), `data-snapshot` (id of a `<script type="application/json">` fallback), `data-api` (default `https://api.tzkt.io`).

Theme with CSS custom properties on the element or a parent: `--td-ink`, `--td-muted`, `--td-paper`, `--td-line`, `--td-accent`, `--td-font`. All rules are scoped under `.tezos-desk`.

Snapshot fallback: `npm run snapshot` pulls the wallet's public numbers from tzkt and writes `public/kit/snapshot.json` (it warns and keeps the old file if the network fails). The build inlines that file into the page; the widget draws it first, then fetches live data and replaces it. If the chain does not answer, the snapshot stays on screen and says so. The pages workflow runs the snapshot step before each build.

Security: token names, image links and other on-chain metadata are untrusted. The widget builds its DOM with `createElement` and `textContent` only, never inserts metadata as HTML, and uses a link or image URL only if it parses as `https:`. `ipfs://{cid}[/path]` is mapped to `https://ipfs.io/ipfs/...` only when the cid is 46 to 100 letters and digits and the path has no `..`, `%2e`, `@`, backslash or `//`; the result is re-parsed and must be on `ipfs.io` under `/ipfs/`. Numbers from the API are range-checked and shown as an em dash if they are not finite or absurd. The live request has a 15 second timeout and then falls back exactly as on failure. Optional `data-images="ipfs"` shows only ipfs-resolved images and gives every other card the placeholder.

Third parties contacted: on load the desk asks `api.tzkt.io` (or your `data-api`) and the image hosts named in token metadata (`ipfs.io` and any https host, unless `data-images="ipfs"`). The door contacts nobody on load. External links carry `rel="noopener noreferrer"`.

### Door (connect and sign in)

`public/kit/tezos-door.js` is a second classic script (`window.TezosDoor = { mount(el), version, getSession(), signOut() }`) that connects a Tezos wallet and signs in with a plain text message. It auto-mounts `[data-tezos-door]` and uses the same stylesheet.

```html
<link rel="stylesheet" href="https://officenoun.xyz/kit/tezos-desk.css">
<script src="https://officenoun.xyz/kit/tezos-door.js"></script>
<div data-tezos-door></div>
```

Attributes: `data-app` (name shown in the wallet prompt, default the page hostname), `data-network` (default `mainnet`), `data-statement` (the one line the user signs, default "sign in to {host}. this moves nothing."; `{host}` is replaced), `data-sdk` (URL of the Beacon SDK browser bundle), `data-sdk-integrity` (sha-384 integrity for a custom `data-sdk`), `data-nonce` (a nonce issued by your server, see below).

Custom SDK rule: a `data-sdk` URL is refused with "no fingerprint for that sdk." unless `data-sdk-integrity` is also given. `http:` is allowed only when the page hostname is `localhost` or `127.0.0.1`. A `window.beacon` that is already on the page is ignored; the door only uses the SDK it injected itself.

Wallet library: the door uses the Beacon SDK, `@airgap/beacon-sdk` 4.8.1, as the single-file bundle `dist/walletbeacon.min.js` (about 4 MB, global `beacon`). The default is `https://unpkg.com/@airgap/beacon-sdk@4.8.1/dist/walletbeacon.min.js`, loaded with a pinned sha-384 integrity hash. It is injected as a script tag on the first click and not before; nothing is fetched on page load. To self-host, copy that file and set `data-sdk` and `data-sdk-integrity`.

Third parties contacted: nobody on page load. After the first click, `unpkg.com` (the SDK file). After that the SDK talks to Beacon's relay servers and, depending on the wallet the user picks, WalletConnect servers, on its own terms.

Flow: connect asks the wallet for the `sign` permission only (the SDK would ask for `operation_request` as well by default; the door overrides that). Sign in builds this text and asks the wallet to sign it as a Micheline string (`0x05 0x01`, a 4-byte big-endian length, the UTF-8 bytes, as hex):

```
Tezos Signed Message: {host}
{statement}
uri: {location.origin}
network: {network}
address: {tz address}
nonce: {data-nonce, or 16 random bytes as hex}
issued: {ISO time}
expires: {issued + 10 minutes, ISO}
```

The statement and app name are limited to printable ASCII (0x20 to 0x7E); any other character becomes `?`, and newlines are flattened.

`data-nonce`: when present it must be 8 to 128 characters of `A-Za-z0-9_-` and is used as the nonce line instead of the browser-made one, so your server can issue it. Anything else puts the door in an error state, "bad nonce.". It is read again at each sign-in, so hand the page a fresh one each time.

Restored sessions: the signed-in session is kept in `sessionStorage` for the tab. On a later page load a stored session is never presented as signed in. If its shape is valid and `issued` is under 12 hours old, the door shows "connected earlier as tz1abc…wxyz. not checked." with "sign in again" and "forget"; otherwise it is discarded. `TezosDoor.getSession()` returns `null` until a fresh sign-in in the current page load.

Events bubble from the element: `tezosdoor:connect` (`address`, `publicKey`, `network`), `tezosdoor:disconnect` (`address`), `tezosdoor:signin` (the session: `address`, `publicKey`, `message`, `payloadHex`, `signature`, `issued`, `expires`), `tezosdoor:signout` (`address`).

The door does not verify anything, and a session is only a claim. A site that wants to trust a sign-in must do all four of these on its server:

1. Recompute the payload from `message` (`05 01`, 4-byte big-endian length, UTF-8 bytes) and check the signature over it.
2. Derive the tz address from the public key itself and compare. Never trust the session's `address` field. Or fetch the account's key from the chain.
3. Issue the nonce yourself (`data-nonce`), remember it, and accept it once.
4. Check that the `Tezos Signed Message:` host line and the `uri:` line match your site, and that now is before `expires`.

Until all four are done, treat the session as an unverified claim. Do not set a cookie, grant access or show account data because of it. The browser only hands the session to your code; this snippet just forwards it for those checks and trusts nothing:

```js
document.addEventListener("tezosdoor:signin", function (event) {
  // your server runs the four checks above and answers with its own session.
  fetch("/api/verify", { method: "POST", headers: { "content-type": "application/json" }, body: JSON.stringify(event.detail) });
});
```

What it does not do: no transactions (it never builds, requests or sends an operation), no keys (it never asks for a secret key or seed phrase), and no signature verification.

CC0. Copy it.

The lot counts on the page ("81 office nouns queued...") come from `lots` in `site.config.json`.

## Unfurls

The build renders today's day number, Noun and trait line into the static HTML, and writes `today.svg` (the hero image) and `card.png` (1200×630, for og:image and twitter:image) into `dist/` and `public/`. Both are gitignored. `siteUrl` in `site.config.json` sets the absolute card URL.

## Build locally

Requires Node 20 or newer. There are no runtime dependencies.

```sh
npm run build
npm run serve
```

Open <http://localhost:8788>. After building, `index.html` also opens directly in Chrome without a local server; `src/index.template.html` is the unrendered source template.

## Deploy with GitHub Pages

The workflow in `.github/workflows/pages.yml` builds `dist/` and deploys it whenever `main` changes. It also runs daily at 08:10 UTC (just after midnight Pacific) so the static day, card and `today.svg` roll over, and can be run manually from the repository's Actions tab. GitHub pauses scheduled workflows after 60 days without repository activity; a push or a manual run turns the schedule back on.

In **Settings → Pages**, set the publishing source to **GitHub Actions** and set the custom domain to `officenoun.xyz`.
